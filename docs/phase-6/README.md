# Phase 6：国家能源体系正式入口采集准入矩阵

## 目标

本阶段先解决国内岗位扩展的基础问题：对中国石油、中国石化、中国海油、国家管网及其研究院、油田、区域公司和集团内技术服务单位的每一个已登记正式频道，明确“如何获取、当前能否访问、页面是否已能解析、还缺什么证据”。

本阶段不把组织数量、频道数量或访问失败写成岗位数量。学生端仍只展示已经通过官方原文和发布审计的岗位。

## 交付内容

- `data/national_source_matrix.json`：四大体系统一招聘入口的当前采集判断、健康观察、字段验证状态和下一步动作。
- `job_hub/national_sources.py`：将组织层级台账展开为“一行一个正式频道”的准入矩阵，并计算覆盖摘要。
- `job_hub/contracts.py`：采集方式、运行状态、扫描结论和岗位字段验证契约。
- 管理员接口：`GET /api/admin/national-source-matrix`。
- CLI：`python -m job_hub.cli national-source-matrix`，支持体系、组织角色和状态筛选。
- 回归测试：确保访问受限来源不能被标记为“扫描成功无匹配”，且每个目标频道都有备份入口和明确的采集判断。

## 统一入口观察

- 中国石油：当前只读请求出现 TLS EOF；状态为 `access_limited / source_unavailable`。
- 中国石化：当前只读请求出现 TLS EOF；状态为 `access_limited / source_unavailable`。
- 中国海油：入口返回 HTTP 200，但正文只有动态脚本壳，没有可直接解析的岗位链接；状态为 `accessible_structure_unverified / structure_needs_adapter`。
- 国家管网：当前只读请求出现 TLS EOF，历史健康记录还出现 robots 403；状态为 `access_limited / source_unavailable`。

上述结果只描述当前网络和当前访问方式，不代表对应单位没有招聘。

## 采集方式分级

```text
官方主页 -> 只确认主体和入口，人工核验
统一招聘门户 -> 逐站验证公开页面、公开 API、ATS 或职位表附件
公开 ATS/API -> 只有发现公开、合规且字段可回溯时才进入自动化
官方附件 -> 受控下载、解析、逐岗位证据和人工复核
访问受限 -> 记录故障，转服务器环境或人工核验，不猜测无岗位
```

当前矩阵中没有把任何统一门户标记为“已验证公开 API”。后续若发现 API，必须同时补充公开访问证据、robots/使用条款、字段样例、回归夹具和失败回退策略。

## 管理员查看

```powershell
python -m job_hub.cli national-source-matrix
python -m job_hub.cli national-source-matrix --runtime-status access_limited
python -m job_hub.cli national-source-matrix --organization-role internal_technical_service
```

HTTP 接口需要 `X-Admin-Token`。矩阵 URL、备用入口、错误观察和字段状态不向学生端公开。

## 本阶段边界

- 没有绕过 TLS、robots、验证码、登录或访问控制。
- 没有把中公、华图、国聘、公众号或其他聚合平台作为正式来源。
- 没有把“登记了 37 个频道”解释为“已经采集 37 个来源”。
- 没有改变 SQLite schema，也没有导入虚构岗位。

下一阶段应按矩阵状态逐个处理：先为可访问动态门户寻找公开字段证据，再为访问受限入口定位服务器可合规访问的正式公告/职位表或人工导入路径。

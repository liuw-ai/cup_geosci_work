# 参考项目方法迁移

本阶段只迁移可审计、合规的工程方法，不照搬会绕过访问控制的做法。

| 参考项目 | 可借鉴方法 | 本项目落地 |
| --- | --- | --- |
| `curl_cffi` | 统一请求层、显式传输配置 | 继续使用 `HTTP_TRANSPORT_MODE=environment/direct` 做网络诊断；不绕过 403/412/robots |
| `Firecrawl` | 附件发现、增量处理、失败重试的流水线思路 | 官方公告页附件登记、哈希存储、解析候选与失败状态分离 |
| `Scrapling` | 站点结构变化时的适配隔离和降级 | 每个来源独立配置/夹具；字段不稳定时停用来源，不猜字段 |
| `JustHireMe` | 标准职位模型、去重、过期下线和质量门 | `RawPosting`、来源证据、状态更新、审计和覆盖报告 |
| `WechatSogou` / `wehire-monitor` | 公众号发现和 OCR 的私有线索流程 | 仍只做发现层，必须回溯单位/政府/高校正式原文后才能发布 |

这些工具不能把受限的中石油、中石化或国家管网入口变成合法可采集来源；真正的突破路径是增加已允许访问的下属单位官方公告和职位表数量，并逐站维护适配器。

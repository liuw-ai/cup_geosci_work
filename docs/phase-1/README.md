# Phase 1 审阅包：数据契约

Phase 1 为地学就业信息站建立可长期维护的“证据和附件底座”。它服务于中国石油大学（北京）地球科学学院的公开就业信息网站，面向资源勘查工程本科生，以及地质学、地质工程、地质资源与地质工程硕士生、博士生。

本阶段不以岗位数量增长为目标。它解决的是后续接入三桶油单位矩阵、31 省官方来源、职位表附件和私有发现线索时，每一条公开岗位如何做到可回溯、可核验、可维护。

## 本阶段完成内容

- 建立来源注册表和单位注册表的离线数据契约，拒绝未知采集器类型、无效 URL、错误父子单位、空别名和无效官方域名。
- 新增 `source_artifacts`：登记官方公告附件的 URL、文件类型、哈希、未来存储路径和处理状态，但本阶段不下载任何附件。
- 新增 `job_evidence`：一个岗位可拥有官方页面、官方记录、附件和字段摘录等多个证据；公开岗位必须至少有一条已核验的官方页面或官方记录证据。
- 新增 `candidate_lead_events`：私有线索从发现到官网定位、内容核验、发布或关闭的状态历史不可丢失。
- 收紧私有线索状态机：不得从 `candidate` 直接跳到 `official_content_verified`，必须先记录已找到的官网原文。
- 提供仅管理员可访问的附件、岗位证据和线索事件接口；公开页面、日报、`/api/jobs` 和学生端不暴露这些私有记录。
- 对旧数据库进行幂等加法迁移：只为已有有效官方链接建立证据索引，不改写岗位正文、来源、日报或抓取历史。

## 本阶段明确不做

- 不新增、启用或访问任何招聘来源，不执行爬虫同步。
- 不下载 PDF/Excel，不解析职位表，不 OCR 扫描件，不保存附件正文。
- 不绕过 robots.txt、登录、验证码、访问控制、反爬或网站使用规则。
- 不改变学生端页面布局、视觉风格、岗位筛选或公开数据范围。
- 不把公众号、中公、华图、国聘、行业媒体等线索直接公开给学生。

## 审阅顺序

1. 阅读 [数据契约](DATA_CONTRACT.md)，确认字段、状态和公开边界。
2. 阅读 [迁移说明](MIGRATION_NOTES.md)，确认现有 SQLite 库的实际影响和回退方式。
3. 阅读 [质量报告](QUALITY_REPORT.md)，确认本地注册表和测试场景的质量门槛。
4. 阅读 [交付说明](DELIVERY_NOTES.md)，核对接口、测试、视觉回归与下一阶段边界。

## 与后续阶段的关系

```text
Phase 0  治理契约、来源准入和质量基线
    -> Phase 1  数据契约、岗位证据、附件台账、线索状态机（本阶段）
    -> Phase 2  官方 PDF / Excel / 扫描件附件受控解析与逐岗位证据
    -> Phase 3  三桶油、重点地勘、高校和国际油服单位矩阵
    -> Phase 4  31 省五类官方来源矩阵
    -> Phase 5  第三方私有发现线索与官网核验工作流
    -> Phase 6  学生端筛选、性能、日报和管理员观测
    -> Phase 7  生产部署、备份、恢复和长期运行治理
```

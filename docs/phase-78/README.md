# Phase 78 附件证据保留与人工复核修正

本阶段修复一个影响学生端真实性和可用性的发布漏洞：附件解析器已经提取的招聘人数、职位代码和岗位资格条件，在候选发布接口重建证据时会被丢弃，导致学生看不到完整字段。

同时，PDF 表格常因断行导致岗位名称、单位或地点碎片化。管理员现在可以在私有复核队列中，在保留原始附件行证据的前提下修正岗位字段；修正必须填写复核说明，低置信度 OCR 候选仍禁止直接发布。

## 变更

- 附件发布接口保留候选已有的扩展字段证据，包括招聘人数、职位代码、岗位资格条件和原始字段名。
- 复核接口支持修正标题、单位、申请链接、地点、日期、学历、专业、摘要和说明，并支持追加/删除字段证据。
- 修正后的岗位仍经过专业、学历、地点、截止日期和官方附件哈希门禁。

## 验收标准

1. 发布岗位的 `field_evidence` 必须保留招聘人数和职位代码（若原始行有这些字段）。
2. 没有 `review_note` 不得进入 `official_content_verified`。
3. 原始附件、行号和哈希不变，任何修正都能追溯到官方公告和复核说明。
4. 学生端不展示 `needs_review`、`rejected`、`expired` 或低置信度候选。

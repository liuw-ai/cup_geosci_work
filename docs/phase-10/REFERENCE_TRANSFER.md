# 参考项目借鉴记录

本阶段只迁移能够提升真实性和可维护性的做法，不迁移绕过访问控制的做法。

| 参考项目 | 本阶段借鉴 | 明确不采用 |
| --- | --- | --- |
| JustHireMe | 来源适配器边界、稳定外部 ID、同步后的去重/过期策略 | 不把聚合站职位直接当官方证据 |
| Scrapling | 把访问策略、请求和解析分层；页面结构变化时让适配器失败并留证 | 不使用指纹伪装、代理轮换或 WAF 绕过 |
| Firecrawl | 结构化字段抽取的配置化思路，以及后续附件流水线的增量方向 | 不把通用抽取结果直接发布；本阶段仍要求专用字段契约 |
| wehire-monitor | “发现 -> 结构化 -> 核验 -> 发布”的状态边界；解析异常进入失败状态 | 不把公众号文章或海报直接展示给学生 |
| WechatSogou | 仅作为未来私有发现层的候选入口 | 本阶段没有采集公众号，也没有把公众号作为来源 |
| curl_cffi | 仅保留为未来合规 HTTP/TLS 兼容性诊断候选 | 不用 TLS 指纹伪装规避 403/412/robots |

BGP 适配器最终仍依赖本项目自己的 `robots` 检查、官方域名允许列表、字段完整门禁、原文证据 URL 和回归夹具；参考项目没有替代这些发布规则。

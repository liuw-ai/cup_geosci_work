### P6-04 自动更新与生命周期防护

- `WORKER_AUTOMATION_ENABLED` 默认关闭。未明确启用时，Worker 只记录 `paused`
  心跳，不会注册来源、采集、扫描、清理或修改岗位数据。
- `/healthz` 会优先报告当前配置状态。隔离库中即使保留旧 Worker 的 `running` 历史
  心跳，在自动化关闭时也只显示 `paused` 与历史时间戳，避免把旧记录误解为本轮正在运行
  的采集或清理任务。
- 在临时数据库的生命周期演练中已验证：30 小时新鲜度、一次扫描缺失、来源/网络失败
  均不能撤回；仅合法的官方关闭证据、截止日期和明确专业不匹配可触发相应状态。备份失败
  会阻止同步并写入 `degraded` 心跳。
- 本阶段没有运行真实同步，也没有启用本地或服务器 Worker。因此“自动更新实运行”仍需
  在项目负责人审阅代码、候选批次和测试后，按独立批准进行一次隔离演练。

## 工作包

### P6-01 第三方真实岗位批量入库

1. 建立批次级台账：发现页、第三方职位表 URL、抓取/提供方式、访问时间、文件类型、字节数、SHA-256、保留文件、批次号、解析行数和处理结果。
2. 每一职位表行只进入私有候选队列；保留行号、岗位代码、专业、学历、地点和批次证据。
3. 对每行绑定官方公告、官方岗位表、官方详情页或官方报名入口。没有岗位级官方证据不得发布。
4. 先以中公的一个合法可访问批次或项目负责人提供的原始职位表完成端到端试点；随后按粉笔、华图、公考雷达、公考资讯网扩展。
5. 每个批次在隔离库执行去重、专业门禁、官方域名核验和学生端预览；通过人工审核才允许形成待合并清单。

### P6-02 三桶油单位身份与入口证据

1. 为 64 个正式目录单位建立逐项证据状态：正式名称、集团归属、组织角色、官方身份页面、单位独立入口、集团共享入口、岗位展示/申请证据、最近复核时间和访问结论。
2. 对 239 个展示候选逐个登记外部身份来源；未补齐不得提升为正式三桶油目录单位或采集源。
3. 明确区分 `unit_specific_entry_verified`、`group_portal_unit_display_observed`、`group_portal_registered`、`official_site_checked_no_unit_entry_found`、`source_unavailable` 与 `group_portal_not_revalidated`。
4. 共享集团平台证明岗位展示，不自动证明下属单位拥有独立招聘系统。

### P6-03 管理员审核工作台

1. 增加独立登录保护的 `/admin` 页面，不在学生端导航中暴露。
2. 展示第三方候选、官方附件候选、来源漏斗和三桶油入口证据摘要。
3. 支持候选的官方 URL、官方岗位表、官方报名入口、单位、地点、专业、学历、截止日期、审核备注和状态流转。
4. 发布动作继续复用数据库的官方域名、官方内容和学生端发布门禁；界面不能绕过 API/数据库契约。
5. 记录审核事件，不向学生端 API 或页面泄露第三方链接、来源健康状态或内部审核状态。

### P6-04 受控自动更新与清理验证

1. 以隔离库演练 Worker 的一次完整周期，先验证备份、失败重试、来源健康、附件候选处理和日报生成。
2. 单独验证：30 小时新鲜度、一次扫描缺失、robots/403/TLS/网络失败、附件失败和来源停用均不会撤回岗位。
3. 验证仅在截止日期已过、专业明确不匹配、官方明确取消/关闭/替换时撤回；无截止日期岗位采用北京时间自然日的 90 天规则。
4. Worker 演练通过后，仍需单独由项目负责人批准，才可以讨论服务器单服务启用。

## 发布门禁

1. 每个工作包都有隔离数据库、证据文件 SHA-256、测试记录和审计报告。
2. Phase 6 合并候选清单必须先由项目负责人审阅；不能直接合并进本地正式数据库或服务器数据卷。
3. 最终发布必须新建不可变镜像、Release Manifest、数据库备份和回滚副本；仅更新明确批准的服务。
4. 不绕过 robots、验证码、登录、403、412、TLS 或网络访问限制；访问受限只能记录为证据状态。

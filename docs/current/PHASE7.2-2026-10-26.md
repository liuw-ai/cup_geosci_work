## 本轮改动

1. 第三方职位表候选现在可以携带明确的 `official_source_id` 绑定提示。该字段只用于官方来源域名核对，不跳过官方内容核验、岗位级字段门禁或学生端发布门禁。
2. 管理员将候选推进到 `official_content_verified` 后，服务器 Worker 在正常同步周期中自动执行与管理员按钮相同的最终转换。只有官方 URL、已登记/人工批准域名、单位、岗位级专业、学历、地点、截止日期和学生端专业匹配全部通过，才会创建公开岗位。
3. 管理员来源漏斗新增第三方职位表漏斗：采集批次、解析行、候选行、官方 URL、官方内容核验、字段完整、专业通过、发布数，以及缺失官方 URL、来源未绑定、未完成核验、字段不完整、拒绝/过期等阻断原因。
4. Web 管理员工作台、增长指标 API 和发现漏斗 API 均使用同一只读漏斗统计；学生端接口不暴露第三方发现内容。
5. `phase-7-1-nightly-readiness-verification` Codex heartbeat 已通过 Codex 自动化管理器暂停。服务器 Worker 的自动同步与 Codex 自动化互不依赖。

## 仍未完成的生产门禁

- R4 的 `749` 条是当前记录口径，不代表 Phase 7.2 已达到 1000/2000；增加数量必须来自真实官方来源捕获和逐岗位证据，不得把候选、历史、过期或第三方原文计入学生端。
- R4 记录的公网 TLS 外部握手仍失败；域名备案/公网链路和腾讯云安全组需要单独解决。
- R4 来源捕获新鲜度、政府台账新鲜度和 57 条附件证据仍未全绿。
- 本地改动需要经过用户批准后才可形成新 release、推送远端、备份服务器数据库并部署。

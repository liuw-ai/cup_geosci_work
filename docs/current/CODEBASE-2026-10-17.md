## 2. 前端与公开接口

入口在 [job_hub/app.py](../../job_hub/app.py)，使用 Flask 创建应用、初始化 SQLite、加载来源并注册路由。模板位于 `job_hub/templates/`，样式和脚本位于 `job_hub/static/`。

### 学生端页面

| 路径 | 功能 |
|---|---|
| `/` | 今日就业日报、实时在招数、方向入口、专业画像入口和重点岗位 |
| `/daily/latest`、`/daily/<日期>` | 最新或指定日期的日报快照 |
| `/jobs` | 全部公开岗位、关键词/方向/省份/学历筛选、分页 |
| `/jobs/<id>` | 岗位详情、单位层级、专业/学历/地点/截止日期证据、官方原文、报名入口和官方岗位表链接 |
| `/government/upcoming` | 已有官方证据但尚未到开放时间的政府岗位，不计入当前在招数 |

| `/about` | 来源说明和收录规则 |

岗位卡已经有“岗位表”入口；详情页已经有“打开官方岗位表”。因此增加第三方职位表对应的官方岗位表链接，前端不需要大幅改版。当前模板尚未统一展示 `source_unavailable`、`专业范围宽泛`、`官方信息不完整` 等四层标签，且部分来源说明文字仍沿用旧的“访问受限不显示”表达，这是后续需要修正的前端契约问题。

## 5. 生命周期实际行为

当前实现已经做了几项关键保护：

1. `pipeline.expire_stale_source_jobs()` 是兼容性 no-op，不因 30 小时新鲜度、捕获缺失或来源停用撤回。
2. `db.withdraw_missing_source_jobs()` 和 `db.withdraw_stale_source_jobs()` 是 no-op，一次扫描未出现或来源过期不改变岗位状态。
3. `db.save_job()` 拒绝没有合法 `withdrawal_reason` 的 `withdrawn` 写入。
4. `withdraw_published_artifact_job()` 只接受 `major_mismatch`、`deadline_passed`、`official_cancelled`、`official_closed`、`official_replaced` 等显式原因。
5. `_public_freshness_filter()` 只按明确截止日期或无截止日期的 90 天自然日规则过滤；`_source_capture_freshness_filter()` 返回 `1 = 1`，不再把 30 小时作为学生端门禁。

仍需注意的实际差异：`complete_source_transition()` 会把旧来源记录标记为 `superseded`，这不是 `withdrawn`，但仍会影响当前可见性；政府复核和模板中还留有旧的“新鲜度/访问受限不显示”描述；现有数据库历史撤回事件不能仅靠新代码自动恢复，必须逐条审计原因。

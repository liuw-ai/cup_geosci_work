# Phase 7: 管理员运行控制与受保护统计

## 范围

Phase 7 在 Phase 6 的岗位证据和候选审核边界上，补充面向长期运行的管理员认证、
隐私保护访问统计以及可审计的 20:00 自动更新周期。

- 学生端导航的“管理员入口”只进入登录页，不显示审核、来源或运行数据。
- 浏览器管理员认证使用 `ADMIN_USERNAME`、`ADMIN_PASSWORD_HASH` 和 Flask 受保护会话；
  密码仅以 Werkzeug 哈希保存在数据库。`ADMIN_TOKEN` 只保留给机器 API。
- 内置角色为 `admin`、`reviewer`、`analyst`。页面路由在会话和权限检查后才会读取私有数据；
  管理员表单继续使用 CSRF，管理员/API 响应禁止缓存。
- 访问统计只存储当天的 HMAC 化访客和会话摘要、日聚合次数以及首次时间戳。不会存储原始
  IP、完整 User-Agent、URL 级浏览历史或学生身份信息。管理员、API、静态资源、健康检查
  和可识别机器人不计数。
- Worker 每日 20:00 周期先同步并清理，再审计和冻结日报。周期以 `worker_runs` 记录；
  备份或同步失败将阻断日报、标记失败并在下一轮重试。网络、robots、访问限制与页面失败
  仍只形成来源状态，不撤回现有岗位。

## r3 运行修复

`phase7-20261023-r3` 在不改变公开门禁的前提下，修复首页实时预览的重复全量重算：
日报卡片现在通过一次批量公开可见性查询进行复核，并对已净化的预览结果使用短时进程缓存。
这避免高并发学生访问反复执行完整日报审计；20:00 Worker 周期仍使用完整日报、备份和审计流程。

## 本地验收

- 目标回归覆盖管理员登录、角色、CSRF、隐私统计排除规则、机器 API、每日运行台账和
  备份失败阻断日报。
- 全量测试必须通过后才可构建发布镜像。
- 本地界面验收地址只可指向 `runtime/phase6/` 下的隔离 SQLite 数据库；不得以页面验收为由
  写入本地正式库或服务器数据库。

## 生产发布边界

发布使用单一 `deploy/compose.yaml`，新的不可变镜像摘要、Release 清单、数据库备份和
回滚副本。发布前在服务器创建并验证备份；发布仅更新 `web` 和经明确配置启用的 `worker`。
浏览器采集器保持不启动，除非另有来源级运行授权。

# 中国石油大学（北京）地球科学学院就业信息站执行计划

本文件是项目后续自动推进的阶段契约。目标不是堆积岗位数量，而是在保证官方真实性和专业匹配的前提下，持续扩大三桶油、地勘、事业编、公务员、高校、外企和相关行业的有效覆盖。

## 1. 产品契约

服务对象固定为中国石油大学（北京）地球科学学院：本科资源勘查工程；硕士、博士地质学、地质工程、地质资源与地质工程。学生端只公开单位官网、政府官网、高校官网、科研院所官网或官方招聘系统中的岗位证据，不公开聚合平台、公众号或内部线索。

学生端必须满足：微信浏览器和桌面浏览器可访问、无需登录、岗位分类清晰、岗位详情可回溯、每日更新、每晚 20:00 生成日报。管理员端必须能看到来源故障、待复核、字段缺失、浏览统计和发布审计。

## 3. 每阶段固定交付包

每个功能阶段都必须在独立分支完成，并包含：

1. 变更说明和架构影响；
2. 数据库迁移说明；
3. 至少一个真实官方来源样例；
4. 单元、集成和回归测试结果；
5. 来源覆盖和字段质量报告；
6. 桌面端、手机端或接口验证记录；
7. Git 提交、阶段标签和远程分支；
8. 已知限制和下一阶段输入清单。

禁止用虚构岗位、旧公告、聚合页面或无法回溯的搜索结果充数。

## 4. 自动验收门禁

阶段完成前由维护流程自动执行以下检查：

### A. 工程门禁

- 全量测试通过；
- `python -m compileall -q job_hub` 通过；
- `docker compose config --quiet` 通过；
- `git diff --check` 通过；
- `audit_database` 返回 `ok: true`；
- 工作树干净，分支和标签已推送。

### B. 来源门禁

- 官方主体、官方域名和栏目路径已记录；
- robots、HTTP、TLS、详情和附件状态分开记录；
- 来源故障不能生成“扫描成功无匹配”；
- 每个岗位都有官方详情、公告行、接口响应或附件页码/行号证据。

### C. 专业门禁

- 本科资源勘查工程单独判断；
- 硕士/博士地质学、地质工程、地质资源与地质工程单独判断；
- 行业关键词、单位名称和公告总述不能替代岗位专业要求；
- 随机抽检中出现错配时，阶段不通过，必须回到匹配规则修复。

### D. 运行门禁

- worker 启动同步、周期同步、20:00 发布和重启补发均可验证；
- 邮件失败不破坏已冻结日报；
- 失败来源进入告警和复核队列；
- 历史岗位自动过期，不得继续显示为在招。

## 5. 不通过时的处理规则

任何一个硬门禁失败，都不能进入下一阶段。处理顺序固定为：

```text
定位失败层级
    -> 保存失败证据
    -> 修复代码/来源契约/数据规则
    -> 重跑针对性测试
    -> 重跑全量门禁
    -> 仍失败则保持当前阶段，不扩大采集范围
```

外部条件导致的阻塞，例如云服务器尚未提供、目标站点临时维护、官方职位表尚未发布，必须标记为 `external_blocked` 或 `source_unavailable`，不能用本机结果替代，也不能伪造通过。

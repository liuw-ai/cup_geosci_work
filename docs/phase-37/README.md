# Phase 37：每日更新与过期岗位清退门禁

日期：2026-09-26  
分支：`phase/37-daily-expiry-gate`

## 本阶段目标

- 确保每次来源同步和日报构建都会按北京时间清退已过截止日的岗位；
- 确保清退岗位不再进入学生端岗位、分类统计、日报新增/更新或未来 7 天提醒；
- 保留岗位历史记录、官方证据和清退事件，避免物理删除破坏审计和重复采集判断；
- 在日报中显示当天已清退数量，便于管理员确认清理链路确实运行。

## 实现边界

`deadline_date < 当天日期` 才会清退。截止日当天仍视为开放，直到下一个北京时间自然日开始。无明确截止日期的岗位仍遵循来源配置的长期/未注明期限规则，不能凭空推断一个日期。

清退操作把 `jobs.status` 从 `open` 改为 `expired`，并写入一条 `job_events(event_type='expired')`。历史数据不物理删除；公开查询统一只读取 `open` 且通过学生端发布门禁的岗位。

## 每日运行链路

```text
worker 启动/每 180 分钟同步
    -> 来源采集与去重
    -> expire_jobs_before(北京时间当天)
    -> 写入 expired 事件
    -> 保存覆盖质量快照
    -> 20:00 最终同步、审计、冻结日报
    -> /daily/latest 与学生端只展示仍在招岗位
```

## 验收

- 本地测试覆盖“过期岗位离开公开查询、历史记录保留、清退事件只计一次、日报显示清退数量”；
- `python -m pytest -q` 全部通过；
- 服务器升级后应检查 `/healthz`、`worker-health`、`/api/coverage` 和当日日报统计中的 `expired` 字段。

# 全院版指标与扩源操作契约

## 唯一目标

服务对象是中国石油大学（北京）地球科学学院学生。学生端只公开中国大陆仍在报名期、可点击回到官方详情或官方附件、具备专业或不限专业依据的岗位。招聘季全国国内岗位扩容目标是 **500 条当前有效岗位**，其中三桶油计划目标为 360 条；海外地点岗位只保留私有审计，不进入学生端或该目标。

候选线索、待复核附件行、过期岗位、历史快照和访问受限页面均不计入有效岗位，也不能以“无岗位”解释。

## 双轴评价

`/api/coverage.dual_axis` 是唯一的公开指标口径，两个轴绝不加权混成一个“完成度”。

| 轴 | 问题 | 分母 | 当前通过条件 |
| --- | --- | --- | --- |
| 国内覆盖轴 | 是否有足够多、足够分散的国内可投岗位 | 500 条国内有效岗位 | 数量、分段来源、单位、省份和集中度门禁均通过 |
| 可靠性轴 | 当前公开记录是否真实、字段完整且可持续更新 | 100 分工程评分 | 官方详情、专业学历、连续刷新、生命周期和质量门禁通过 |

全院数据就绪仅在以下条件全部为真时成立：国内有效岗位达到 500；各目标分段的来源、单位和省份门禁都通过；单一来源不超过 25%，前五来源不超过 75%，单一单位不超过 15%；可靠性评分至少 90；官方详情和明确专业学历匹配均至少 95%；至少 90% 已启用来源连续两次成功刷新；生命周期审计通过。

域名、HTTPS 和公网服务器健康是独立部署门禁，不能用数据评分替代。

## 来源漏斗

### 读取侧新鲜度

`source_health.last_success_at` 表示同步请求完成时间，不能替代官方快照
的实际捕获时间。凡来源配置了 `max_age_hours`，必须同时有完整成功捕获证据
写入 `source_capture_freshness`；学生端查询在数据库读路径直接过滤超时或缺失
证据的来源。worker 仍负责撤回、事件审计和恢复发布，读路径过滤本身不写库。

管理员通过 `python -m job_hub.cli source-funnel` 或受保护的 `GET /api/admin/source-funnel` 查看来源账本。每个来源的状态必须按以下顺序解释：

```text
来源登记 -> 合规访问 -> 列表发现 -> 岗位详情 -> 字段证据
-> 专业学历匹配 -> 当前截止日期 -> 去重 -> 学生端发布
```

账本把来源分为 `not_scanned`、`running`、`access_limited`、`failed`、`scanned_with_matches`、`scanned_without_current_match` 和 `disabled`。`running` 不等于失败；`access_limited` 不允许继续反复调试绕过访问策略，应保留低频监控并转向已登记的官方备用入口或其他独立来源。

候选数、证据完整数、人工复核数和开放匹配数都只表示该来源**最近一次完成运行**的漏斗指标；当前发布岗位会受到截止日期、新鲜度和发布门禁影响，二者不能直接相除。

只有最近运行满足 `discovered >= evidence_complete >= open_matching` 且人工复核数不超过发现数时，才允许用它讨论来源的漏斗效率。旧适配器若缺少同范围证据计数，会被标记为 `incomplete`；计数超过发现总数会被标记为 `invalid`。两种状态都不影响既有岗位的独立发布审计，但必须在继续依赖该来源扩容前修复指标写入。

## 扩容批次规则

1. 每批至少接入两个独立官方来源，优先省级人社/地质系统、中央地勘单位和独立三桶油下属单位。
2. 每条准备发布的岗位必须有官方岗位详情或行级附件证据，以及专业、学历、地点、当前期限；人数仅在官方披露时填写。
3. 先运行两次完整刷新，再接受为可持续来源；失败、部分分页或访问受限均不替换最后一次完整快照。
4. 批次后必须重新计算国内覆盖、前五来源占比、单位和省份覆盖。若集中度恶化，停止向主导来源继续加量。
5. 每日 worker 继续执行截止清退、来源新鲜度清退、已停用来源退出、政府附件复核与日报快照；这些操作保障真实性，但不应替代新增独立来源工作。

## 可复现核验命令

PowerShell 本地开发环境可使用：

```powershell
$env:PYTHONPATH = (Get-Location).Path
python -m pip install -r requirements-dev.txt
python -m compileall -q job_hub
pytest -q
python -m job_hub.cli coverage --record --output .\runtime\coverage.json
python -m job_hub.cli source-funnel --output .\runtime\source-funnel.json
python -m job_hub.cli batch-audit --output .\runtime\batch-audit.json
```

`coverage.json` 是动态当前值，不应由阶段文档中的历史数字替代。发布前使用已验证的在线 SQLite 备份生成该报告；损坏或不完整的临时副本不能作为生产证据。

## 招聘批次台账

`data/recruitment_batches.json` 是扩容的唯一批次规划入口。每个批次绑定官方入口、已登记来源、目标岗位数和必需字段；`batch-audit` 只读取当前学生端公开岗位和最近采集运行，输出：

- 当前批次岗位数与缺口；
- 来源是否已登记；
- 最近一次完整运行和连续两次成功刷新比例；
- 官方详情、专业、学历、地点、截止日期证据完整率；
- 单位、省份覆盖以及下一步动作。

批次台账不替代 `coverage` 双轴指标，也不会把候选、访问受限、待人工复核或过期记录计入有效岗位。中国海油、CNPC、中石化和国家管网先按 2027 校招批次核验，事业编和公务员按年度职位表批次导入；只有批次门禁通过后才允许启用或替换生产快照。

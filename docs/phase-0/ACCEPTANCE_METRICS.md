# 验收指标与质量门槛

## 1. 原则

岗位总数是观察值，不是质量结论。后续版本必须同时报告岗位覆盖、来源质量、字段证据、结构多样性和运行状态。任何指标增长都不能掩盖官方原文缺失、来源故障或专业误匹配。

## 2. 不可降低的公开发布门槛

| 编号 | 门槛 | 通过条件 |
| --- | --- | --- |
| P1 | 官方证据 | 公开岗位的 `official_evidence_url` 指向允许的 A 级或符合条件的 B 级正式来源。 |
| P2 | 招聘主体 | 招聘单位和公告/招聘系统主体可识别；不能用模糊转载主体替代。 |
| P3 | 在招状态 | 岗位是开放、长期开放、截止日未公布或已过期中的一种明确状态；未知状态不能伪装为在招。 |
| P4 | 明确匹配证据 | 标为“明确专业匹配”的岗位有专业与学历原文证据。 |
| P5 | 去重与历史 | 同一岗位的重复发现应合并；原始链接、首次发现和最新核验时间可追溯。 |
| P6 | 故障诚实性 | 扫描失败、来源禁用、访问受限和栏目变更不许输出为“没有岗位”。 |

P1 到 P6 是发布门槛，不是“达到一定比例即可”的优化目标。任何一条不满足时，岗位应进入待复核或被拒绝，而不是为了丰富页面而发布。

## 3. 持续质量指标

| 指标 | 定义 | 当前基线 | 后续目标与解释 |
| --- | --- | --- | --- |
| 公开岗位官方证据完整率 | 在招岗位中含正式原文链接的比例 | 52/52，100% | 始终为 100%。 |
| 明确匹配证据完整率 | 标为明确匹配的岗位中，专业和学历都存在可定位原文证据的比例 | Phase 0 未单独计算 | Phase 1 开始单独记录，目标为 100%。 |
| 地点字段完整率 | 在招岗位中能确定省份、城市或海外国家/地区的比例 | 省份明确 3/52，5.8% | 先记录“已知/未说明”状态，再逐步提高，不从单位名猜测。 |
| 截止日状态完整率 | 具明确截止日、长期招聘、系统未公布固定期限或未知状态的比例 | 明确日期 4/52，7.7% | Phase 1 后要求状态 100% 可解释；不强制所有公告都给出日期。 |
| 来源集中度 | 最大单一来源在在招岗位中的占比 | 53.85% | 高于 50% 触发扩源告警，不因告警隐藏真实岗位。 |
| 类别集中度 | 最大岗位类别在在招岗位中的占比 | 82.69% | 高于 70% 触发扩源告警，说明就业路径不够均衡。 |
| 活跃来源广度 | 有在招匹配岗位的来源数 / 成功扫描来源数 | 7 / 26 | 增加国内官方来源的真实有效广度，不以候选 URL 充数。 |
| 省份五类矩阵 | 人社、自然资源、地质、事业单位、公务员五类目标的状态 | 15 verified / 155 | 先提升正式核验，再启用自动采集。 |
| 附件解析成功率 | 受控下载并成功形成可核验岗位行的官方附件比例 | 尚未实现 | Phase 2 建立基线和失败分类后再设目标。 |
| 私有线索转化率 | 找到官方原文并安全发布的线索比例 | 0 条线索 | Phase 5 建立；不能以转化率为由降低原文要求。 |
| 100 人模拟 | 匿名固定队列中有明确匹配的学生数和不同岗位数 | 100 人有明确匹配，20 条明确岗位匹配 | 不得把“100 人”解释成 100 个不同岗位或真实就业结果。 |

## 4. 省份覆盖的正确判断

某省只有在五类角色来源均已正式核验、相应已启用来源的最近一次扫描均成功、所有扫描均未发现开放匹配岗位时，才可以写“本轮未发现匹配岗位”。以下任一情况只能写“覆盖尚未完成”或“来源当前不可用”：

- 栏目未定位或路径发生变化；
- robots/使用规则尚未核验；
- 403、412、429、登录、验证码、TLS 或网络异常；
- 解析器失败、附件无法解析或来源尚未扫描；
- 来源只存在第三方转载，没有正式原文。

## 5. 发布前测试与证据要求

每个版本都必须交付：

```text
变更说明
数据库迁移说明（无迁移也必须明确写“无”）
目标测试结果
真实官方来源样例及原文链接
手机与电脑页面检查结果
质量指标与前一标签的对比
Git 提交、分支和可回退标签
```

每个新增来源适配器必须有离线测试样本。测试不能依赖实时外网成功，避免因某个官网临时波动而让回归测试失去意义。

## 6. 性能与运营指标

性能不能仅凭主观感受判定。Phase 6 将通过浏览器测量建立如下基线：岗位筛选页面、单位图谱页面、日报页面的加载时间和交互完成时间；数据库查询数；缓存命中率；移动网络下的核心页面可用性。

在测量数据产生前，不承诺具体毫秒数。当前的工程要求是：网页请求不执行外部抓取，不执行 OCR，不全量重算覆盖报告；这些工作应由后台 worker 或日内快照承担。

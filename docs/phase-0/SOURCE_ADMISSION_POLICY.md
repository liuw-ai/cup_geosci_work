# 来源准入与公开发布规范

## 1. 来源等级

| 等级 | 可接受主体 | 作用 | 是否可直接成为学生端证据 |
| --- | --- | --- | --- |
| A | 招聘单位官网、政府官网、正式招聘系统、正式人事考试平台 | 公开岗位的首选来源 | 可以，仍须经过岗位有效性和字段检查。 |
| B | 高校就业网、高校/科研院所官网、经确认的校内正式就业信息 | 补充发现和正式岗位发布 | 仅在来源主体明确且岗位可回溯到正式招聘信息时可以。 |
| C | 公众号、教辅平台、行业媒体、招聘聚合站、社交平台 | 私有发现线索 | 不可以。必须先找到 A 或符合条件的 B 级原文。 |

来源等级描述的是证据强度，不等于岗位一定适合目标学生。专业、学历、地点、截止日和在招状态仍需逐岗位判断。

## 2. 一个来源必须具备的登记信息

Phase 1 开始，任何新来源都应在来源注册表中至少保存下列信息。缺少关键项的来源只能停留在候选状态：

```text
source_id
来源名称与正式运营主体
来源等级、就业路径和省份/国家覆盖范围
主入口 URL 与备用官方入口 URL
允许域名清单
公开访问方式与 robots/使用规则核验结论
列表页、详情页和附件入口的样例 URL
采集频率、单次最大请求量、超时和退避策略
解析器版本、测试样本位置、负责人和最近审阅日期
启用状态、健康状态和停用原因
```

“已登记”不代表“已启用”；“入口可访问”不代表“存在当前适配岗位”；“发现网页”不代表“可对学生公开”。

## 3. 来源生命周期

下列状态是后续来源治理的目标词汇。当前注册表已有 `enabled`、来源健康和抓取运行记录；Phase 1 会把这些状态统一为可审计的状态转换。

```text
candidate
  -> official_identity_verified
  -> access_policy_verified
  -> adapter_fixture_verified
  -> enabled
  -> degraded / blocked / retired
```

状态说明：

| 状态 | 允许自动采集 | 可解释为“无岗位” | 管理动作 |
| --- | --- | --- | --- |
| candidate | 否 | 否 | 找到正式主体和当前栏目。 |
| official_identity_verified | 否 | 否 | 已确认官方主体，但尚未完成访问和页面验证。 |
| access_policy_verified | 否 | 否 | 公开访问规则允许，但仍需样例和解析测试。 |
| adapter_fixture_verified | 否 | 否 | 解析样例通过，待审核后启用。 |
| enabled | 是 | 仅在最近扫描成功且没有开放匹配时，且满足省份矩阵条件。 | 受限速、失败隔离和质量门槛约束。 |
| degraded / blocked | 否 | 否 | 记录原因，寻找同一主体的备用官方入口。 |
| retired | 否 | 否 | 保留历史原因和历史岗位，不再访问。 |

## 4. 访问与采集规则

- 只访问事先登记的公开入口和允许域名。
- 先核验 robots.txt 和公开访问规则；不确定时停用自动访问。
- 使用固定、礼貌的请求频率、有限重试、指数退避和失败隔离。
- 不处理登录、短信验证、验证码、个人 Cookie、接口密钥、代理池、指纹伪装或绕过访问控制。
- `403`、`412`、`429`、TLS 异常、栏目迁移和页面结构变化应被记录为来源状态，不能用技巧强行突破。
- 发现新的官方入口时，先进入候选来源，不得直接加入定时 worker。

## 5. 附件与职位表规则

官方公告中的 PDF、Excel、Word 或扫描件可能包含真正的岗位行。Phase 2 引入附件流水线前，附件只能作为公告的支持性材料，不能被假装成已结构化的职位数据。

Phase 2 的每个附件解析结果必须保留：

```text
公告原文 URL
附件原始 URL
下载时间和 SHA-256 哈希
文件类型、解析器版本和失败信息
岗位行号或页码/坐标证据
提取的专业、学历、地点、人数、日期和报名方式
人工复核状态
```

扫描 PDF 经 OCR 得到的字段应默认进入待复核队列，不能只因模型或 OCR 给出高置信度就自动标记为“明确专业匹配”。

## 6. 第三方发现线索规范

公众号、教辅平台、行业媒体和招聘聚合网站只用于发现线索。目标状态如下：

```text
candidate
  -> official_url_found
  -> official_content_verified
  -> published

candidate / official_url_found
  -> need_review / rejected / expired
```

公开发布前必须满足：正式原文链接存在、招聘主体已确认、原文仍有效、岗位字段与原文一致、公开岗位写入的 `official_evidence_url` 指向正式原文。当前系统已经要求候选线索在 `official_content_verified` 后才可转为公开岗位；Phase 1 将补齐更细的状态约束和审计记录。

## 7. 每个专用适配器的验收材料

一个来源在启用前必须提交：

1. 官方主体与入口的核验说明。
2. 至少一个公开列表页、详情页和附件样例，适用时分别提供。
3. 保存在测试目录中的脱敏 HTML/JSON/文档样本，避免测试期间反复访问外部网站。
4. 解析测试：标题、单位、原文 URL、地点、时效和专业/学历证据。
5. 失败测试：空列表、页面改版、无附件、访问受限和解析失败不能产生虚假岗位。
6. 备用官方入口及来源故障时的管理员处理说明。

# Phase 2 交付说明

## 变更摘要

- 新增 `job_hub/attachments.py`：官方附件发现、robots/域名约束、受控下载、哈希存储、PDF/Excel/CSV/DOCX 解析和候选生成。
- 扩展 `job_hub/contracts.py`：附件处理状态、附件候选审核状态和状态转移校验。
- 扩展 `job_hub/db.py`：原始行台账、私有候选、幂等更新、证据绑定和发布前条件。
- 扩展 `job_hub/app.py` 与 `job_hub/cli.py`：管理员发现、处理、查看和发布接口/命令。
- 扩展配置、依赖和 Docker 镜像；附件目录始终位于应用数据目录内。
- 修复相对附件目录在 Docker 中的解析语义，并将候选发布、岗位和证据写入收敛为单事务。
- 新增 `tests/test_attachments.py`，不使用真实招聘内容，只验证本地文件和访问边界。

## 建议人工演练

1. 选择 `data/sources.json` 中一个已核验、公开可访问的官方公告页。
2. 用管理员令牌调用 `POST /api/admin/artifacts/discover`，只检查登记结果。
3. 审阅附件来源、文件类型、robots 和原文字段后，才调用处理接口。
4. 对候选逐条填写核验说明；低置信度或字段缺失的行保持私有。
5. 发布前运行 `audit`，确认公开岗位同时有官方页面和附件证据。

本阶段不应把“解析成功”当成“岗位真实有效”，也不应为追求数量而降低官方来源和人工核验门槛。

# Phase 14：专业分类注册表与官方入口契约

本阶段的目标是把“地学院专业”从散落在 Python 关键词中的隐含规则，提升为可审阅、可测试、可回退的版本化数据契约，并登记一个已从单位官网确认的官方招聘入口。

## 本阶段完成

- 新增 `data/major_taxonomy.json`，明确四个目标专业的教育层级、学科门类、目录代码、精确名称和相邻发现词。
- 新增 `job_hub/major_taxonomy.py`，校验专业注册表，禁止重复精确名称，并让七个学生画像从注册表构建。
- 修正 `资源勘查工程` 与 `勘查技术与工程`、`地质工程` 与 `地质资源与地质工程` 的边界；相邻专业只进入“需核验”，不再自动变成“明确匹配”。
- 对 `地质资源与地质工程` 进行短语遮蔽，避免其中的“地质工程”子串把窄专业画像误判为独立专业要求。
- 运行历史岗位重索引：备份 `runtime/job_hub.sqlite3` 后检查 162 条记录，按新规则重分类 40 条。
- 从中海油服官网首页确认其公开招聘链接 `http://cosl.zhiye.com/`，新增禁用的 `cosl-career` 登记；当前网络访问失败只记录为入口故障，不解释为无岗位。

## 明确边界

本阶段没有把中公、华图、公众号或职位聚合页作为学生端证据，也没有把中海油服 ATS 的失败响应伪装成“没有岗位”。专业目录代码用于解释和筛选，具体报名资格仍以单位公告原文为准。

## 后续工作

下一阶段优先在服务器直连环境复测 `cosl-career`，再为可公开访问的三桶油下属单位公告页和职位表分别建立适配器。没有详情页、专业字段和原始附件证据的入口保持禁用。

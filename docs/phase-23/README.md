# Phase 23：事业编与公务员职位表准入审计

本阶段把事业单位和公务员职位表从“来源登记”推进到可审阅的逐岗位证据台账。目标不是把公告标题批量变成岗位，而是为后续扩源建立统一的年度、附件和专业门禁。

## 已完成

- 新增 `job_hub/government_positions.py`：
  - 统一事业单位/公务员行级字段；
  - 校验官方公告 URL、职位表附件 URL、页码/Sheet/行号证据；
  - 强制 `verified_open` 行同时具备地点和截止日期；
  - 将 `manual_review_required`、`source_unavailable` 与“扫描成功无匹配”区分开；
  - 输出专业、学历、地点、截止日期和证据完整率。
- 新增 `data/government_position_registry.json`：
  - 安徽省地质矿产勘查局 2026 年岗位表的 2 条真实地学岗位行；
  - 北京人社官方公告样例；
  - 国家公务员局年度职位表状态，明确为待核验，不把历史职位表伪装成当前岗位。
- 新增 CLI：

```text
python -m job_hub.cli government-position-audit --today 2026-09-25
```

## 发布边界

安徽两条岗位的专业和学历证据已经明确，但岗位表行没有单列工作地点，因此当前记录保持 `manual_review_required`，不会被本台账自动宣称为学生端在招。补齐官方地点证据并人工复核后，才可转换为 `verified_open` 并进入既有发布门禁。

国家公务员职位表按年度发布。当前台账只登记国家公务员局官方入口和待核验状态；在确认当年度官方公告、PDF/Excel 附件、专业代码、学历、地点、招录人数和报名截止日期之前，不创建任何公务员岗位。

## 下一步

1. 在服务器直连环境重新发现安徽、山东、河南、天津等省级事业单位最新公告和附件。
2. 对每个附件记录 SHA-256、页码/Sheet/行号，并补齐岗位地点证据。
3. 当国家公务员局发布当年度职位表后，使用同一台账导入职位代码、招录机关、专业代码和学历要求。
4. 仅将 `verified_open` 且 `explicit_match`/`unrestricted_match` 的记录交给学生端发布接口。
